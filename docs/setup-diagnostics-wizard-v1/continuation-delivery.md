# Мастер настройки и диагностики: рабочая локальная версия

Откройте **http://127.0.0.1:18038/setup**. Мастер проверяет зарегистрированного
исполнителя, Git, настройки секретов, туннеля и состояние движка. Локальная
модель объясняет результаты и предлагает действия. Выполнение проходит через
«Сформировать план» → подтверждение; модель сама действия не запускает.

Это текущая инструкция вместо прежней `corrective-delivery.md`. Исторические
отчёты о блокировках и неудачных попытках сохранены. Квалификация локальной
версии принята двумя независимыми Reviewer. Текущий коммит выпуска ещё проходит
свои нативные ревью; итоговое наблюдаемое состояние после них записывается в
`C:\nqt37\FINAL_DELIVERY.json` и в журнал продолжения. Дата и sprint_id отчёта
позволяют отличить его от старой сдачи.

## Запуск и вход

1. Если установка остановлена, выполните **`C:\nqt37\Запустить мастер.cmd`**.
   Команда последовательно запускает собственный тестовый Git, клиент и мастер.
   Уже работающие компоненты проверяются по владельцу и повторно не создаются.
   При ошибке следующие шаги не выполняются; сообщение остаётся в окне.
2. Откройте адрес выше. Если нужен вход, выполните **`C:\nqt37\Вход в мастер.cmd`**,
   введите десятисимвольный код со страницы и нажмите на ней «Проверить
   подтверждение сессии». Оператор — `madoev`; административный секрет в браузер
   не передаётся.
3. Обновите диагностику. Проект **9000** в этом отдельном экземпляре служит для
   настройки: `UNKNOWN / STORE_UNAVAILABLE` для его истории ожидаемы. История
   настоящей автономной самопроверки находится в проекте **9010**.
4. Задайте вопрос помощнику или сформируйте план разрешённого действия. Перед
   применением проверьте план. Ответ модели помечен как рекомендация, а
   недоступные данные сохраняют статус неизвестных.

Если спринт уже выполняется, открывайте работающий адрес напрямую. Команды
запуска/остановки сохраняют проверку отсутствия активной работы и могут отказать;
это не повод обходить её или завершать процессы по старому PID. Сначала остановите
нужное задание штатной операцией движка. **`C:\nqt37\Остановить мастер.cmd`**
останавливает только доказанный собственный сервер и отказывает при активной
работе. Клиент и локальный Git остаются доступными зависимостями.

## Границы этой установки

Изолированный WSL-исполнитель квалифицирован для **`docs-only-v1`**: небольшого
репозитория с явно разрешёнными документами. Это не подтверждение произвольной
разработки и запуска кода. Используется отдельный дистрибутив
`NginxQaWorker-20261104`; Docker и глобальные настройки WSL не изменялись.
Доступ ChatGPT берётся из существующего входа; снимок не содержит refresh token.
При истечении доступа исполнение прекращается с ошибкой: повторите обычный
поддерживаемый вход, затем штатную проверку готовности. Ключи через чат не нужны.

Для живого Telegram-развёртывания отсутствуют настройки именно этого бота:
bot token, webhook credential и разрешённый Telegram actor. Вход с реального
телефона/планшета ещё не проверен. Ранее граница Cloudflare TLS/HTTP прошла
24 настоящие проверки на версии PR17 `89f7f09` 3 ноября 2026; её тестовый туннель
потом остановлен. Это историческое доказательство шлюза, а мастер сейчас
остаётся приватным на loopback. Эти пункты — конкретные внешние данные и
приёмка, а не запрос дополнительных разрешений.

## Восстановление

При отказе запуска сохраните текст ошибки и используйте текущие helpers;
не подменяйте owner marker, коммит или журналы базы. Для идемпотентного запуска
после включения компьютера достаточно пользовательской команды выше.
Подробный порядок, проверки владения и защищённая резервная копия описаны в
[инструкции квалификации](continuation-qualification.md#using-the-installed-local-version).
Откат требует доказать и штатно остановить текущего владельца, проверить
совместимость сохранённых настроек с актуальной историей. Старую базу нельзя
безусловно копировать поверх новой. Старый remote-коммит установки сохранён.

Исходники выпускаются в существующий [draft PR18](https://github.com/chartjs333/nginx-qa/pull/18)
поверх [PR17](https://github.com/chartjs333/nginx-qa/pull/17). Автоматического
объединения с `main` нет; будущая приёмка Telegram не подменяется локальным GO.
