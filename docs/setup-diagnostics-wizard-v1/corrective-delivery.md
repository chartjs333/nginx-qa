## Открыть мастер

1. Откройте адрес выше. Если сервер остановлен, выполните
   `C:\nqt37\Запустить мастер.cmd`. Уже работающий собственный сервер повторно
   не запускается. Проверяются закреплённый Git-коммит и ownership marker.
2. Если страница показывает код входа, выполните
   `C:\nqt37\Вход в мастер.cmd`, введите код и нажмите на странице
   «Проверить подтверждение сессии». Имя оператора — `madoev`. Административный
   ключ читается локально из защищённой конфигурации и не передаётся браузеру.
3. Выберите проект и обновите диагностику. В этом отдельном экземпляре проект9000
   зарегистрирован для настройки, но его native история не копировалась с18035:
   поэтому UNKNOWN/STORE_UNAVAILABLE для такой истории ожидаемы. Реальный
   тестовый спринт находится в отдельном проекте9010.
4. Сформируйте план нужного разрешённого действия, прочитайте его и примените.
   Если план устарел, обновите диагностику и создайте новый. Если потерян ответ
   уже применённого действия, повторяйте тот же запрос с тем же ключом;
   не создавайте новую операцию вслепую.
5. Карточки истории помечены как сохранённые. Нажмите «Обновить статус», чтобы
   получить текущий статус движка. Сохранённая карточка APPLYING сама по себе
   не означает, что спринт всё ещё выполняется.

Для остановки только этого сервера используйте
`C:\nqt37\Остановить мастер.cmd`. Инструмент сверяет команду владельца и его
дерево процессов, затем посылает сигнал только проверенной консоли. Данные
и Git-история сохраняются. Старые серверы18035/18036 и Madoev EEG не затрагиваются.

Проверены удалённый Git-коммит, освобождение reservation/branch lease,
идемпотентный повтор и сохранность результата после перезапуска сервера и
повторного именованного входа. Живой клиент управлялся присутствующим оператором;
временный bridge и Git daemon после проверки остановлены.

Веб-сервер сохраняет ownership-привязку к65662f6. Его веб-исходники имеют те же

checkout может преобразовывать LF/CRLF: byte hashes относятся к указанным
исходным файлам, Git-содержимое сверяется после нормализации переводов строк.

## Почему полный live-релиз имеет NO_GO

- Windows10 Pro22H2 build19045.6456 и установленный CLI0.161 не обеспечивают
  требуемый MXC backend. `--check` корректно блокирует автономный клиент.
  Более слабая проверенная изоляция пропускала сетевой доступ и не допущена.
  Обновить только CLI недостаточно. Нужен поддерживаемый квалифицированный
  хост с успешным `--check`, либо отдельно реализованный и проверенный backend.
- Настоящий LLM-консультант здесь не прошёл live-приёмку. Сейчас работает
  явно обозначенная детерминированная подсказка. Для live gate нужен явный
  tool-free Responses provider с защищённой ссылкой на ключ и настроенной моделью
  либо отдельно квалифицированная изоляция существующего клиента. Новые ключи
  и платные ресурсы этой работой не создавались.
- Telegram, мобильный вход и Cloudflare Tunnel сохраняют внешние gates PR17.
  Из этого локального теста нельзя вывести их готовность.

После устранения этих ограничений проведите новый неизменяемый self-test profile
с новыми опубликованными manifest commit и assigned branches, реальным
автономным клиентом, двумя независимыми проверками и доказанным завершением/Stop.
Старый завершённый профиль нельзя повторно выдавать за новый запуск. Проходите
дальнейшую приёмку через поддерживаемый native recovery/repair или новый
разрешённый спринт; не редактируйте control DB и историю принятых результатов.

Draft PR зависит от PR17. `main` не объединялся. Для отката остановите собственный
экземпляр и сохранитеC37; не переписывайте ownership marker, принятые ветки
или существующие спринты. Контракты и доказательства:
[corrective-qualification.md](corrective-qualification.md),
[corrective-contract.md](corrective-contract.md),
[managed-codex-client.md](managed-codex-client.md).

Draft PR: https://github.com/chartjs333/nginx-qa/pull/18. База — ветка PR17; автоматического слияния нет.

## Исправление локального входа после security review

Первый release result fad38ab отклонён: статический marker не доказывал,
какой процесс получает административный ключ на локальном порту. В отдельном
native rework команда входа исправлена. Она открывает TCP-соединение без HTTP,
сверяет владельца именно этой установленной пары адресов/портов, listener,
полную команду и исполняемый файл launcher, а также время создания каждого
процесса в его дереве. Только после проверки читается ключ. Запрос идёт по тому
же сокету; автоматическое переподключение и перенаправления запрещены.

12 целевых тестов прошли, включая чужой listener, подменённый PID, повторное
использование PID, подмену сокета и безопасные ошибки. Настоящий именованный
вход на18038 также прошёл с реальным CIM-коллектором. Копии проверенного helper,
тестов и квитанции находятся в evidence/corrective-release. Доступ к собственной
папке инструментов, четырём командам и PID-квитанции ограничен текущим
пользователем и SYSTEM. Доверенные операторские файлы и установка остаются
границей доверия; защита от скомпрометированного аккаунта оператора или
администратора ОС не заявляется. Другие ACL хоста не изменялись.
