## Запуск, вход и работа

1. Выполните **`C:\nqt37\Запустить мастер.cmd`**, если установка остановлена.
   Команда проверяет или запускает собственный Git, клиент и мастер по порядку.
   При ошибке она останавливается; уже работающие компоненты повторно не создаются.
2. Откройте адрес мастера. Для входа выполните **`C:\nqt37\Вход в мастер.cmd`**,
   введите десятисимвольный код со страницы, затем нажмите на странице
   **«Проверить подтверждение сессии»**. Используется постоянный оператор `madoev`.
   Административный секрет не передаётся в браузер или чат с моделью.
3. Выберите проект и обновите диагностику. **9000** здесь зарегистрирован для
   настройки; `UNKNOWN / STORE_UNAVAILABLE` для его локальной истории ожидаемы.
   Настоящая завершённая автономная самопроверка находится в проекте **9010**.
4. Задайте вопрос помощнику либо нажмите **«Сформировать план»** у разрешённого
   действия. Проверьте последствия и подтвердите применение. Ответ модели сам
   по себе не выполняет операцию.

Если работа уже идёт, используйте открытый интерфейс. Команды запуска и
остановки сохраняют проверки отсутствия активной работы. Для остановки мастера
используйте **`C:\nqt37\Остановить мастер.cmd`**: она останавливает только
подтверждённый собственный сервер, а при активной работе отказывает. Клиент и
локальный Git остаются доступными зависимостями. Сначала завершайте нужное
задание штатной операцией движка.

## Если ответ на применение потерялся

Нажмите **«Проверить результат исходного запроса»**. Проверка читает исходный
план и квитанцию; повторное применение требует отдельного подтверждения и
использует тот же ключ. После потери входа снова подтвердите сессию тем же
оператором и повторите проверку результата.

Закрытие подтверждения через Escape, крестик или **«Закрыть, сохранив запрос»**
не отменяет уже отправленную операцию. Пока результат не установлен, сохраняется
исходный запрос и блокируется создание другой операции. Перезагрузка той же
вкладки сохраняет его идентификатор. Не закрывайте вкладку и не очищайте её
хранилище до выяснения результата: это состояние привязано к вкладке.

Ошибка доступа может прийти после выполнения действия. Отсутствие квитанции
при проверке тоже не доказывает, что отправленный запрос никогда не выполнится.
Используйте проверку исходного запроса и его прежний ключ. Когда сервер явно
подтвердил `PLAN_STALE` с квитанцией `BLOCKED`, старый план не выполняется:
обновите диагностику и сформируйте новый план. Срок плана — 120 секунд.

Клавиатурный фокус возвращается после закрытия подтверждения. Задержанные ответы
не возвращают старую ошибку и не перехватывают фокус после нового входа или нового
действия. Внешний переход Tab в интерфейс самого браузера остаётся обычным
поведением браузера.

## Перезапуск и откат

Обычный перезапуск: остановите мастер его командой, затем выполните команду
запуска. Она проверяет фактического владельца каждого процесса; старые PID
и старые launch-receipts для остановки не используются.

Откат к прежнему закреплённому исходнику — отдельное контролируемое обновление:
сохраните согласованную защищённую копию текущего состояния; докажите отсутствие
активной работы; штатными текущими инструментами остановите собственные сервер
и idle-клиент до изменения их общей папки; затем сверьте выбранный immutable
ref, marker владельца и новую версию helpers. После запуска проверьте владельца,
историю и восстановление квитанций. Не копируйте старую БД поверх новой истории.
Предыдущие refs `fdafbf58`, `a1841e4` и `65662f6` сохранены. Защищённые резервные
копии содержат секреты и остаются только в операторском журнале.
Подробности владения и восстановления: [инструкция квалификации](ui-focus-qualification.md#current-operator-entry-points).

## Границы локальной сдачи

Квалифицированный исполнитель поддерживает `docs-only-v1`: небольшие репозитории
с явно разрешёнными документами. Реальные Telegram bot/webhook credentials,
разрешённый актор и физическая проверка на телефоне/планшете остаются внешними
условиями. Узкий экран Edge не подменяет проверку Telegram на телефоне.

Мастер остаётся приватным. Текущий публичный gateway выключен и отвечает
`503 GATEWAY_OFFLINE`; включённый изолированный gateway в тесте отклоняет пять
приватных путей с 404. Исторические 24 настоящие проверки Cloudflare относятся
к PR17 `89f7f09` от 2026-11-03, его туннель остановлен.

Исходники собраны в [draft PR18](https://github.com/chartjs333/nginx-qa/pull/18)
поверх [PR17](https://github.com/chartjs333/nginx-qa/pull/17). `main` и PR не
объединяются в этой локальной сдаче. Прохождение локальных тестов не является
заявлением о пройденном hosted CI или полном публичном запуске Telegram.
