Автоматизированная квалификация: **PASS, 148 тестов**. Полная готовность к
автономной эксплуатации не подтверждена: изоляция Codex на этом компьютере

Проверенный код: `8a4b38f2e0ffbdd13a596f316c6e33b65452ab60`. Последующее

## Что проверено вживую

На собственном экземпляре `http://127.0.0.1:18038/setup` браузер Edge в headless
режиме прошёл именованный вход, выбор двух проектов, 16 диагностических проверок,
Plan/Cancel/Apply и историю после перезагрузки. Ответ консультанта был явно
детерминированным fallback, без притворного ответа модели. Ошибок JavaScript нет.

В отдельном тестовом Git-репозитории проекта9010 существующий движок сам выдал
одно задание автору и два задания независимым Reviewer. Реальные агенты
выполнялись последовательно через присутствующего оператора. Клиент создал и
опубликовал коммит `f1148f56787fd905d6880583e89205b9b67cdab9`; движок принял
обе проверки и завершил спринт. Проверены SUCCEEDED в мастере, отсутствие новых
заданий при повторе исходного apply, освобождение branch lease и проектного
слота. После реального перезапуска собственного сервера именованный вход
восстановил доступ к той же успешной квитанции и истории.

Первую попытку остановили штатно после обнаружения зависания Git for Windows
на передаче через git://. Её история сохранена. Обход применяется только к
проверенному git:// push; checkpoint OUTPUT_READY сохраняет уже проверенный
результат при сбое публикации. Новый самостоятельный сетевой тест подтверждает
реальную передачу пакета и удалённый SHA. Конфигурация Git не изменяется.

## Границы результата

Сервер остаётся закреплён на `65662f69db52c27b6c0972ccec8031cfb68a02fc` согласно
своему ownership marker. Git blobs его веб-кода совпадают с квалифицированной
версией (рабочие копии могут различаться LF/CRLF); исправленный отдельный клиент
использовал8a4b38f. После проверки
клиент оператора и временные Git daemon остановлены. Это не постоянно работающий
автономный воркер. `main`, Madoev EEG и старые серверы18035/18036 не обновлялись.

Windows10 build19045.6456 не поддерживает требуемый MXC backend; CLI0.161 также
старее допуска. Реальные пробы более слабой изоляции пропускали сетевой доступ,
поэтому такой режим не разрешён. Обновление только CLI не устранит ограничение ОС.
Нужен квалифицированный поддерживаемый хост с успешным `--check` либо отдельно
реализованный и независимо проверенный адаптер изоляции.

Консультант поддерживает явно настроенный Responses-транспорт без tools, но
живой провайдер здесь не настроен и не проверен. Детерминированный режим работает.
Telegram, мобильный вход и Cloudflare из PR17 не получили новых live-доказательств.
Подробные контракты: [corrective-contract.md](corrective-contract.md) и
[managed-codex-client.md](managed-codex-client.md). Эти ограничения требуют NO_GO
для полной live-приёмки, а не подмены результата фиктивным GO.

## Исправление доказательства после независимого REJECT

Результат2074132 отклонён Reviewer: старый браузерный тест мог увидеть уже
существующую карточку SUCCEEDED и перезагрузить страницу до ответа Apply.
Его утверждение о live Apply/Reload недействительно. История REJECT сохранена;
движок выдал отдельное rework-задание. Код продукта не менялся.

Повторный реальный браузерный прогон ждёт конкретный POST к новому plan_id,
проверяет свежий SUCCEEDED-ответ, ровно его operation_id в DOM и тот же ID
в серверной истории и DOM после reload. Отменённый план не применялся.
Новый отчёт и исполнявшийся harness включены в evidence/corrective-qualification.
Старые карточки истории показывают сохранённые квитанции; текущий статус
движка получается кнопкой «Обновить статус».
